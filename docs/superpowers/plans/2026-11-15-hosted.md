# Hosted Control Unit Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Prepare the working Control Unit for authenticated Netlify or Vercel deployment.
**Architecture:** Static React + same-origin serverless API + durable PostgreSQL; local collector pushes read-only imported records. Existing SQLite mode remains supported.
**Tech Stack:** Existing stack plus pg, serverless-http, and PGlite for SQL integration testing.
**Spec:** docs/superpowers/specs/2026-11-15-hosted-design.md

## Global Constraints
- Never invent data or write Rio source files.
- Hosted functions never run local import or persist data in temporary SQLite.
- Every business number remains traceable to execution records.
- Secrets stay server-side/device-local; no shared account connectors or actual credential values in tracked files.
- User requests no mid-build questions; no deployment or cloud resources created without actual account context.

## Review Focus
- Concurrent daily quota reservation across function instances stays within cap (Task 1).
- Failed snapshot replacement preserves prior records and isolates collectors/API origins (Tasks 1–2).
- Hosted APIs reject anonymous reads, hostile origins, missing config and wrong bearer tokens (Task 2).
- Collector never sends a partial or oversized projection or follows an HTTP redirect with credentials (Task 3).
- Hosted refresh/login/key setup labels reflect hosted capabilities and collector freshness (Task 4).

### Task 1: Durable asynchronous store
Files: server/postgres-store.ts, server/postgres-driver.ts, database/schema.sql, tests/postgres.test.ts. Interface server/store-contract.ts permits sync SQLite or async Postgres. Implement same methods and atomic quota SQL. Write failing integration tests against PGlite, implement and verify.

### Task 2: Hosted API boundary
Files: server/app.ts, server/config.ts, server/auth.ts, server/analysis.ts, tests/hosted-api.test.ts. Accept ExecutionStore and await methods; implement fail-closed hosted config, canonical HTTPS host/origin, cookie login/session/logout and separate mandatory bearer ingestion/sync. Sync handler injectable into createApp; no local importer in hosted refresh. All local tests must still pass. Test first.

### Task 3: Collector and platform adapters
Files: server/sync.ts, collector.ts, cloud.ts, api/index.ts, netlify/functions/api.ts, vercel.json, netlify.toml, tests/collector.test.ts. Validate snapshot/provenance and derive collector-scoped IDs; enforce 3 MB/5,000 records. Collector once/watch sends HTTPS with redirects rejected, prints counts/diagnostics without secrets and never writes sources. Cloud entrypoint initializes Postgres with no local imports/listen/timers. Platform adapters preserve /api path. Test first.

### Task 4: Hosted UI and delivery
Files: src/**, README.md, docs/deployment.md, .env.example, package.json, tsconfig.json. Login/401 flow and runtime-aware copy, hosted refresh read-only, actual ingestion URL, source freshness. Package scripts for collector/build; prepare both providers. Full tests/build/audit, independent review, platform bundle checks. Clearly report actual remote deployment not performed.
